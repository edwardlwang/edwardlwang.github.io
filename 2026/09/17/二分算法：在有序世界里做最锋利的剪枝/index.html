二分算法：在有序世界里做最锋利的剪枝

前言

二分算法（Binary Search）大概是所有算法里最“反直觉”的一个：思路简单到一句话就能说完，但真正写对却意外地困难。Knuth 曾说过，虽然二分查找早在 1946 年就被提出，但直到 1962 年才出现第一个完全正确的实现。而在实际工程与竞赛中，二分的边界错误（死循环、漏解、多解）几乎是最高频的 bug 来源之一。

二分算法的本质，是利用数据的单调性，每次将搜索区间缩小一半，从而把 O(n)O(n)O(n) 的线性查找优化到 O(log⁡n)O(\log n)O(logn)。但二分真正的威力远不止“查一个数”——当问题的答案具有单调性时，我们甚至可以对答案本身进行二分，这就是所谓的“二分答案”。

本文系统梳理二分算法的两种写法、三种题型、边界处理技巧与经典例题，代码示例统一使用 C++17。

一、什么是二分算法

二分算法的核心思想只有一句话：

在单调的区间内，每次取中点，根据中点与目标的关系，砍掉一半不可能包含答案的区间。

以最简单的“有序数组中查找目标值”为例：

每次循环区间长度减半，因此时间复杂度为 O(log⁡n)O(\log n)O(logn)。

为什么是 mid = left + (right - left) / 2 而不是 (left + right) / 2？

因为 left + right 可能溢出 int。这在 left 和 right 都接近 INT_MAX 时会发生，属于经典陷阱。养成写 left + (right - left) / 2 的习惯。

二、二分算法的适用条件

二分并不局限于“有序数组”。它真正需要的是单调性，即：

存在一个判定函数 check(x)，使得在答案区间内，check 的结果呈现“前 false 后 true”或“前 true 后 false”的单调形态。

只要满足这一点，就可以对 x 所在的值域二分。

因此二分算法适用于两类问题：

1. 查找型：在有序序列中找目标

  • 有序数组查找某个值
  • 找第一个 ≥ target 的位置（lower_bound）
  • 找最后一个 ≤ target 的位置（upper_bound 变体）

2. 判定型（二分答案）：答案具有单调性

  • 求“最小的最大值”或“最大的最小值”
  • 判定“在限制 X 下能否满足某条件”，且 X 越大越容易满足

判定型二分的套路是：把最优化问题转化为判定问题。

例如：“求让所有船在 D 天内运完的最小载重” → “载重为 C 时能否在 D 天内运完？”这个判定关于 C 单调，于是可以二分 C。

三、二分的两种写法

二分最容易出错的地方就是边界。业内有两种主流写法，选一种并坚持到底，是写好二分的诀窍。

写法一：闭区间 [left, right]

区间两端都可能是答案，循环条件 left <= right，退出时区间为空。

要点：right = mid - 1 和 left = mid + 1 保证区间每次严格缩小，不会死循环。

写法二：左闭右开 [left, right)

区间左端包含、右端不包含，循环条件 left < right，退出时 left == right 即为答案。

要点：right = mid 而不是 mid - 1，因为 mid 本身可能是答案。这种写法更简洁，被 C++ STL 与多数竞赛选手采用。

两种写法的选择建议

场景 推荐写法
查找具体值（找到即返回） 闭区间 [left, right]
查找边界（第一个满足条件的位置） 左闭右开 [left, right)
二分答案 左闭右开 [left, right) 或闭区间均可

铁律：无论用哪种写法，都要保证区间每次严格缩小，否则会死循环。

四、二分的三种经典题型

题型一：查找精确值

代表：LeetCode 704. 二分查找

在有序数组中查找 target，找到返回下标，否则返回 -1。

题型二：查找边界

代表：LeetCode 34. 在排序数组中查找元素的第一个和最后一个位置

关键在于把“等于 target”拆解为两个不等式：

  • 第一个位置：第一个 nums[i] >= target 的下标
  • 最后一个位置：第一个 nums[i] > target 的下标减一

要点：只需要实现一个 lowerBound，通过传入 target 和 target + 1 就能同时求出左右边界。

题型三：二分答案

代表：LeetCode 875. 爱吃香蕉的珂珂

这是二分最强大也最常考的形式：答案空间本身有序，对答案进行二分。

问题：有 n 堆香蕉，第 i 堆有 piles[i] 根。珂珂每小时吃 k 根，吃某一堆时若剩余不足 k 也必须吃完这一堆才能换堆。求在 h 小时内吃完所有香蕉的最小 k。

思路：

  • 答案 k 的取值范围是 [1, max(piles)]。
  • 给定 k，可以在 O(n)O(n)O(n) 时间内判断能否在 h 小时内吃完。
  • 若 k 越大越容易满足（单调性），可以二分。

要点：

  • 结果可能很大，累加用 long long。
  • left < right 循环结束后 left 就是最小可行解。
  • 判定函数必须严格遵循单调性，否则二分失效。

五、二分答案的通用模板

当题目出现以下特征时，就应考虑二分答案：

  • 求“最小化最大值”或“最大化最小值”
  • 存在一个阈值 X，使得“X 可行”具有单调性
  • 直接求解困难，但判定某个答案是否可行容易

六、经典例题

例题 1：搜索旋转排序数组（LeetCode 33）

问题：升序数组在某个位置旋转后，查找目标值。

思路：旋转后数组分为两段升序。每次取 mid，判断 mid 落在左段还是右段，再判断目标值是否在有序的那一段内。

复杂度：O(log⁡n)O(\log n)O(logn)

要点：nums[left] <= nums[mid] 判断哪半边有序，然后只需在有序列中判断目标是否落于区间内。

例题 2：寻找两个正序数组的中位数（LeetCode 4）

问题：给定两个有序数组，求它们合并后的中位数，要求时间复杂度 O(log⁡(m+n))O(\log(m+n))O(log(m+n))。

思路：对较短数组进行二分，将其划分为左右两部分，使得左部分的最大值 ≤ 右部分的最小值，同时保证左部分总元素数为 (m+n+1)/2。

复杂度：O(log⁡min⁡(m,n))O(\log \min(m, n))O(logmin(m,n))

要点：这是二分法中最精妙的题目之一。用 INT_MIN 和 INT_MAX 处理越界，避免大量特判。

例题 3：寻找峰值（LeetCode 162）

问题：数组 nums 中相邻元素不相等，找到任意一个峰值元素的下标（大于左右邻居）。

思路：虽然数组无序，但可以“利用坡度进行二分”。若 nums[mid] < nums[mid+1]，则右侧必有峰值；否则左侧必有峰值。

复杂度：O(log⁡n)O(\log n)O(logn)

要点：二分并不要求数组全局有序，只要每一步能判断答案在左还是在右即可。

例题 4：在排序数组中查找第一个错误的版本（LeetCode 278）

问题：从版本 1 到 n，存在一个分界点，之后都是错误版本。求第一个错误版本，接口为 isBadVersion(v)。

思路：典型的下界二分。

复杂度：O(log⁡n)O(\log n)O(logn)

例题 5：搜索二维矩阵（LeetCode 74）

问题：m × n 矩阵每行升序，且下一行第一个元素大于上一行最后一个元素。判断 target 是否存在。

思路：整个矩阵可以视为长度为 m × n 的一维有序数组。

复杂度：O(log⁡(mn))O(\log(mn))O(log(mn))

例题 6：分割数组的最大值（LeetCode 410）

问题：将非负整数数组分成 k 段连续子数组，使各段和的最大值最小。

思路：经典二分答案。“最大段和 ≤ X 是否可以分成不超过 k 段”对 X 单调。

复杂度：O(nlog⁡S)O(n \log S)O(nlogS)，其中 SSS 为数组元素总和。

要点：判定函数要做到“能在贪心扫一遍后返回 true/false”，否则无法配合二分。

例题 7：狒狒吃香蕉（LeetCode 875）

前面已详细介绍，此处略。

例题 8：第 K 小的数对距离（LeetCode 719）

问题：给定整数数组，求所有数对距离中第 k 小的距离。

思路：二分答案 + 双指针计数。答案空间是 [0, max - min]，判定 距离 ≤ X 的数对数量是否 ≥ k。

复杂度：O(nlog⁡n+nlog⁡D)O(n \log n + n \log D)O(nlogn+nlogD)，DDD 为最大差值。

要点：双指针计数是二分答案的常见搭档，二者结合能处理很多计数型问题。

七、C++ STL 中的二分

标准库已经封装好二分函数，能省下手写边界的风险。

函数 作用 返回值
lower_bound(b, e, x) 第一个 ≥ x 的位置 迭代器
upper_bound(b, e, x) 第一个 > x 的位置 迭代器
equal_range(b, e, x) 等于 x 的区间 [lo, hi) pair
binary_search(b, e, x) 是否存在 x bool

注意：这些函数要求区间有序（默认按 < 升序）。若自定义比较器，需传入第三个参数。

手写还是用 STL？

  • 题目是“查找边界”型，优先用 STL，不易错。
  • 题目是“二分答案”型，STL 用不上，需手写。
  • 竞赛中若担心性能，可手写，但建议保留 STL 写法作对拍。

八、常见陷阱

  1. 中点计算溢出
    写 mid = (left + right) / 2 在 left + right 接近 INT_MAX 时会溢出。始终用 left + (right - left) / 2。

  2. 死循环
    若 left = mid 且 mid = (left + right) / 2，当 right = left + 1 时 mid == left，left = mid 原地踏步。解决办法：在 left = mid 分支时改用 mid = (left + right + 1) / 2。

  3. 循环条件写反
    闭区间用 while (left <= right)；左闭右开用 while (left < right)。两者不能混用。

  4. 更新边界时漏掉加一减一
    闭区间中 left = mid + 1 和 right = mid - 1 必须写全，否则死循环；左闭右开中 right = mid，不能写成 mid - 1。

  5. 判定函数非单调
    二分答案的前提是 check(x) 单调。若判定函数在某些 x 上“抖动”，二分会漏解。写完后可用小数据暴力验证。

  6. 整数除法方向
    求最大可行解时 mid 要向上取整，否则 lo = mid 会导致死循环。这一点极易被忽略。

  7. 返回值选择错误
    闭区间写法退出后，left 可能等于 right + 1，不能直接返回 left；需要用变量记录答案，或改用左闭右开写法。

  8. 浮点数二分的精度
    浮点数二分应固定迭代次数（例如 100 次）而不是用 left < right 判断，避免精度问题。

十、总结

二分算法是少数“看上去简单、写起来难”的算法之一。掌握它的关键在于：

  1. 明确单调性：数据有序，或答案具有单调性——这是二分的前提。
  2. 选定一种写法：闭区间或左闭右开，不要混用；两种写法都熟练更好。
  3. 保证区间缩小：每次更新边界都要让区间严格变小，否则死循环。
  4. 识别二分答案：见到“最小化最大值”或“最大化最小值”，先想二分答案。
  5. 善用 STL：查找型问题优先用 lower_bound / upper_bound，把边界交给标准库。

一句话概括二分算法：

每次砍掉一半不可能的世界，直到答案在剩余区间里只剩下唯一可能。

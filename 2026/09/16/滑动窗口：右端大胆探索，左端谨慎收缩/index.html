滑动窗口：右端大胆探索，左端谨慎收缩

发表于2026-09-16|更新于2026-09-16|Algorithms
|总字数:3.7k|阅读时长:14分钟|浏览量:

前言

滑动窗口（Sliding Window）是一种用于处理数组、字符串等线性结构上连续子区间问题的算法思想。它通过维护一个可以伸缩的区间 [left, right]，在保证区间始终满足某种约束的前提下，将原本需要 O(n2)O(n^2)O(n2) 或 O(n3)O(n^3)O(n3) 的暴力枚举优化到 O(n)O(n)O(n)。

这个区间之所以说“会呼吸”，是因为它右端不断向外探索，左端则根据约束谨慎收缩——一伸一缩之间，恰好扫过所有可能的候选区间，且两端从不后退。

滑动窗口的本质是双指针（Two Pointers）的一种特化形式：两个指针同向移动，共同维护一个区间。相比动态规划和贪心，滑动窗口的适用场景更具体，但一旦识别出来，代码往往短小精悍，且时间效率极高。

本文系统梳理滑动窗口的适用条件、通用模板、经典题型与常见陷阱，代码示例统一使用 C++17。

一、什么是滑动窗口

滑动窗口算法维护两个指针 left 和 right，表示当前考察的连续子区间 [left, right]。算法的一般流程如下：

  1. 初始化 left = right = 0，窗口为空。
  2. 不断右移 right，将新元素纳入窗口，并更新窗口的统计信息。
  3. 当窗口不满足约束时，不断右移 left，缩小窗口直到再次满足约束。
  4. 在每次窗口合法的时刻记录答案。
  5. 重复步骤 2–4，直到 right 到达数组末尾。

关键在于：left 和 right 都只增不减，因此每个元素最多被访问常数次，总复杂度为 O(n)O(n)O(n)。

复杂度：O(n)O(n)O(n)

二、滑动窗口的适用条件

滑动窗口并非万能，它仅适用于满足以下条件的问题：

1. 求解对象是连续子区间

问题要求的是数组或字符串上的一段连续区间（子数组、子串），而非子序列。

2. 窗口的合法性具有单调性

随着 right 右移，窗口的“违规程度”单调递增；随着 left 右移，窗口的“违规程度”单调递减。这种单调性是窗口能够单向收缩的前提。

例如，“窗口内元素之和 ≤ S”、“窗口内不包含重复字符”这类约束天然满足单调性；而“窗口内元素之和恰好等于 S”这类约束则不满足，需要借助哈希表或额外技巧，不能简单套用模板。

3. 窗口信息可增量维护

窗口扩展或收缩时，统计量（和、频率、最大值等）可以在 O(1)O(1)O(1) 或均摊 O(1)O(1)O(1) 时间内更新。若需要每次重新扫描窗口（如窗口最大值用普通遍历），则退化到 O(nk)O(nk)O(nk)，失去意义。

三、滑动窗口的两种类型

1. 定长窗口（Fixed-size Window）

窗口大小固定为 k。每次右移 right 一步，同时右移 left 一步。

关键区别：

  • 求“子数组和等于 k 的个数”这类问题，因为约束不具单调性，需用前缀和 + 哈希表，而非滑动窗口。
  • 求“和至少为 target 的最短子数组”（元素全正），可以用滑动窗口，因为和具有单调性。
  • 若数组含负数，“和”不再具有单调性，滑动窗口失效。

五、经典例题

例题 1：无重复字符的最长子串（LeetCode 3）

问题：给定字符串 s，求不含重复字符的最长子串长度。

思路：变长窗口 + 哈希表记录字符最后出现的位置。

复杂度：O(n)O(n)O(n)

要点：left 直接跳到重复字符的下一位，避免逐个字符收缩。lastPos[c] >= left 的判断确保不会跳到窗口之外。

例题 2：长度最小的子数组（LeetCode 209）

问题：给定正整数数组 nums 和目标值 target，求和 ≥ target 的最短连续子数组长度。

思路：变长窗口，窗口和 ≥ target 时收缩左边界。

复杂度：O(n)O(n)O(n)

要点：题目限定元素为正整数，保证窗口和的单调性。若元素可能为负，需改用前缀和或二分。

例题 3：找到字符串中所有字母异位词（LeetCode 438）

问题：给定字符串 s 和 p，找出 s 中所有 p 的字母异位词子串的起始索引。

思路：定长窗口（窗口大小 = len(p)）+ 计数数组。

复杂度：O(n⋅∣Σ∣)O(n \cdot |\Sigma|)O(n⋅∣Σ∣)，其中 ∣Σ∣=26|\Sigma| = 26∣Σ∣=26，可视为 O(n)O(n)O(n)。

要点：定长窗口进入即出。用固定大小的数组代替哈希表，常数更小。

例题 4：最小覆盖子串（LeetCode 76）

问题：给定字符串 s 和 t，求 s 中涵盖 t 所有字符的最短子串。

思路：变长窗口 + 哈希表 + 有效字符计数。

复杂度：O(n+m)O(n + m)O(n+m)

要点：valid 记录已满足数量要求的字符种类数，避免每次比较整个哈希表。这是“最短覆盖型”问题的经典写法。

例题 5：滑动窗口最大值（LeetCode 239）

问题：给定数组 nums 和窗口大小 k，返回每个窗口内的最大值。

思路：定长窗口 + 单调队列（双端队列维护递减序列）。

复杂度：O(n)O(n)O(n)，每个元素最多进出队各一次。

要点：单调队列是滑动窗口求极值的关键数据结构。窗口内最大值永远在队首。

例题 6：替换后的最长重复字符（LeetCode 424）

问题：给定字符串 s 和整数 k，最多可以将 k 个字符替换为任意字符，求替换后最长的相同字符子串长度。

思路：变长窗口，窗口内“非最多数字符”的数量不能超过 k。

复杂度：O(n)O(n)O(n)

要点：maxCount 只增不减。因为只有更大的窗口才可能产生更优解，缩小窗口时不需同步减小 maxCount，这正是代码中 if 而非 while 的原因。

例题 7：水果成篮（LeetCode 904）

问题：数组 fruits 表示每棵树上的水果种类，你有两个篮子，每个篮子只能装一种水果。求最多能采摘多少棵树（连续子数组）。

思路：变长窗口，窗口内不同水果种类数不超过 2。

复杂度：O(n)O(n)O(n)

例题 8：最大连续 1 的个数 III（LeetCode 1004）

问题：给定二进制数组 nums 和整数 k，最多可将 k 个 0 翻转为 1，求最长连续 1 的长度。

思路：变长窗口，窗口内 0 的数量 ≤ k。

复杂度：O(n)O(n)O(n)

六、常见陷阱

  1. 约束不具单调性却硬用滑动窗口
    最典型的反例是“子数组和恰好为 k”。因为数组中可能存在负数，窗口和不再随右端点单调递增，滑动窗口会漏解或死循环，必须改用前缀和 + 哈希表。

  2. 窗口收缩用 if 还是 while
    当约束是“≤ k”这类硬性上限时，必须用 while，确保收缩到合法为止。当答案只依赖最大窗口、且缩小窗口不可能产生更优解时（如例题 6），可用 if 使窗口只减一寸，保证窗口长度不减。

  3. 哈希表忘记清理零值键
    例如 count[c] 减到 0 后，如果没 erase，count.size() 仍然包含该键，会导致“不同种类数”判断出错。

  4. 边界条件处理不当
    空数组、k > n、k = 0、target 小于最小元素等，需要在代码开头做判断。

  5. 窗口信息未能增量更新
    例如求窗口最大/最小值时，如果每次窗口变动都重新遍历，复杂度会退化到 O(nk)O(nk)O(nk)。此时应使用单调队列或有序结构。

  6. left 越过 right
    收缩窗口时需保证 left <= right。在某些写法中（如例题 6 用 if），left 可能与 right 同步推进，但绝不能超过。

八、总结

滑动窗口是一种将双指针技巧应用于连续区间问题的算法。掌握它的关键在于：

  1. 识别问题类型：是否是连续子数组/子串？约束是否具有单调性？
  2. 选择窗口类型：定长窗口用“右进左出”，变长窗口用“扩展—收缩”。
  3. 明确窗口状态：和、频率表、单调队列、有效计数等。
  4. 判断收缩方式：用 while 还是 if，取决于约束与答案的关系。
  5. 警惕失效场景：约束不单调、含负数、窗口统计无法增量维护时，滑动窗口不适用。

一句话概括滑动窗口：

维护一段会呼吸的区间，右端大胆探索，左端谨慎收缩，两端永不后退。
